# 测试文档 — 示范域 / 核心循环

> **示范文件**：展示当**四种变更类型并存**时，`tests.md` 如何跟着状态走。
> 这是理解「测试文档也是活文档」的关键案例——落地后可删除本示范域。

## 四种状态如何映射到测试文档（先看这张表）

| 版本 | 类型 | 测试文档里怎么体现 |
|---|---|---|
| **V2** | feature | 第 1 节的 `AC-1` 测试点，视为**当前生效** |
| **V2.1** | patch | 第 1 节的 `AC-P001-N` 测试点，同样是当前生效 |
| **V1** | sunset | 原 V1 的测试点**不删除**，在「变更记录」标注作废原因（历史上下文） |
| **V4** | blueprint | **不进本文件** —— 未定型方案没有验收标准，也就没有测试点 |

> **关键区别**：spec 日落时测试点可以移除（代码会删），但**本文件的记录不删**——
> 它回答「当时测过什么、为什么现在不测了」，与 specs 的 sunset 哲学一致。

> **patch 与 sunset 都改了测试范围，都必须留痕**：
> patch 是「新增了要测的东西」，sunset 是「过去要测的东西不再适用」。
> 只记前者会让读者以为测试覆盖一直在增长，而不知道有东西被下线了。

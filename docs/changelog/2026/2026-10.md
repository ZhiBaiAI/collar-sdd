### 2026-10-09 · chore · 新增「让 AI 读懂存量代码库」调研蓝图

- **Spec**：— （模板自身能力，落在 [docs/wiki/blue-print/](../../wiki/blue-print/) 探索层）
- **影响面**：`docs/wiki/README.md`（索引）、`docs/wiki/blue-print/README.md`（清单）、新增 `docs/wiki/blue-print/[调研]让AI读懂存量代码库.md`
- **变更**：收录外部方法调研——存量代码库无设计文档时，模型指向源码树会先耗尽上下文再虚构结构，因此建自底向上的 README 层级（先写叶子、父层从子层 README 加自身文件总结），并配三条纪律：只准自底向上、AI 永不批准自己的产物、每条 README 带退役声明。同时记录外部给出的评审成本量级（每叶 5–10 分钟、叶层错误率约一半）与四条待决问题。成熟度停在 `[调研]`，未进任何规范性模块。
- **破坏性**：无
- **关联**：外部来源 [EECS 498 AASE 课程仓库](https://github.com/eecs498-aase/materials)（`egm/` 目录），方法原始出处 Dave Rensin《Elephants, Goldfish and the New Golden Age of Software Engineering》

### 2026-10-28 · feat · 新增约定 C-008「执行时间与接手等待分开记账」

- **Spec**：— （过程知识，落在 [docs/runbook/conventions.md](../../runbook/conventions.md)）
- **影响面**：`docs/runbook/conventions.md`（新增 C-008 与索引行）、`AGENTS.md`（关键约定速查表 +1 行，112 行）
- **变更**：补上门禁治理容易漏掉的一侧。原约定都在约束「怎么做得对」，缺一条说明「为什么加了门禁周期却没明显变短」。C-008 要求按轮核算：`周期 = Σ(每轮:执行时间 + 接手等待) + 外部等待`，并行分支只沿关键路径计算；另记零填报的流动效率 `流动天 ÷ 流逝天`。静默只作排查入口，先还原最近一次交接再判断是卡点还是悬置；回执、责任接手、问题解除三态分开记录；计时对象是问题而非群。并明确报干预收益前须扣掉自然恢复、设同期未介入对照。
- **破坏性**：无
- **关联**：外部依据 天猫技术《数字员工（效能篇）》2026-10-26（编码人工介入 0.5 轮/需求而周期只缩短一到三成；261 段静默「等人回应」占 66%、其中 64% 自行恢复）

### 2026-10-31 · feat · 新增约定 C-009「提效只认端到端三项，不认生成速度」

- **Spec**：— （过程知识，落在 [docs/runbook/conventions.md](../../runbook/conventions.md)）
- **影响面**：`docs/runbook/conventions.md`（新增 C-009 与索引行）、`AGENTS.md`（关键约定速查表 +1 行，113 行）
- **变更**：补上「提效怎么算」这一环。原约定管的是做得对不对（C-008 管周期怎么记），缺一条说明「凭什么说这次改动静真的提效了」。C-009 要求只报端到端三项：交付时间、人工判断与返工成本、上线缺陷与长期维护成本；同时按任务类型分档声明预期，不得把日抛型任务的加速比当复杂系统的预期。并给出两笔必须扣的账——验证税，以及编码仅占约三成的阿姆达尔上限；推论是先把验证容量与证据链补齐，再扩大自动生成范围。
- **破坏性**：无
- **关联**：外部依据 嘀嗒出行《一个人用 AI 像开挂，团队协作就打架》2026-10-29（千人团队两年实测：好的提效三成多、差的没有提效，AI 投入全压在占三成的编码环节）、腾讯云开发者《代码秒出，验证排队？AI Coding 的隐性账单》2026-10-30（验证税、阿姆达尔上限、Faros AI 与 Sonar 研究）

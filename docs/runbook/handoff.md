# docs/runbook/handoff.md — 跨会话长任务交接协议（按需）

> **触发边界：单次会话能做完并验证的任务，不要写交接文件。**
> 仅当任务跨越多次会话、即将切换 Agent，或需要中途暂停待人介入时使用。

---

## 1. 为什么只写「书签」，不复述对话

长任务最常见的失败不是做错，而是上下文耗尽或换会话后丢失「做到了哪、踩过什么死路、什么算完」。
交接文件是**状态书签**，不是聊天记录摘要——只记新会话接手必需的硬事实。

---

## 2. 最小交接模板（临时落盘，任务完结即删除）

建议放在仓库临时忽略路径（如 `.collar/handoff.md`，不提交污染主干）或当前进行中的 PR/Issue 描述里：

```markdown
# Handoff — ⟨任务一句话目标⟩

- **终态 / 当前状态**：进行中 / blocked / needs-input / budget-exhausted
- **目标与约束**：⟨最终交付物 + 不能碰的边界⟩
- **完成判据**：⟨可机械判定的验收命令或 AC-N 编号⟩
- **已完成与证据**：
  - ⟨步骤 1⟩ —— 证据：⟨文件路径 / 已跑命令与退出码⟩
- **已否决的路径（防重复踩坑）**：
  - ⟨试过 X，因 Y 不可行⟩
- **下一步（精确到文件或命令）**：
  1. ⟨下一个具体动作⟩
- **阻塞项（需人工裁决）**：⟨无 / 具体问题与选项⟩
```

---

## 3. 四类明确终态（避免无限空转）

| 终态 | 触发条件 | 动作 |
|---|---|---|
| `done` | 外部验证证据全部通过 | 汇报结果与证据，清理临时交接文件 |
| `blocked` | 缺权限、环境不可用、连续 3 次同错未解（C-003） | 立即停下，带着真实报错交接 |
| `needs-input` | 命中关键事实缺口或重大取舍（C-005） | 列出选项与推荐项，等人拍板 |
| `budget-exhausted` | 上下文临近上限或耗时超预期 | 保持工作区可构建，落盘交接书签后切新会话 |

---

## 4. 质量检验：「换 Agent 检验」

写完交接后只问一句：**如果现在立刻开一个全新会话、不给任何历史聊天记录，新 Agent 只读这份书签和仓库代码，能不能无缝继续下一步？** 不能，就补齐缺失的路径、命令或约束。

# 排障剧本

> 由 `collar-runbook` 在 commit 时自动抽取填充，也可随时主动追加。
> **排障第一原则：遇到不可解释的现象，先怀疑环境，再怀疑代码。**

---

## 格式

```markdown
## ⟨故障一句话描述⟩

- **现象**：⟨观测到了什么（含报错原文关键词）⟩
- **根因**：⟨为什么会这样⟩
- **解法**：⟨一步步怎么做⟩
- **预防**：⟨怎么让它不再发生 —— 这条最重要，没有预防的剧本是流水账⟩
- **证据**：⟨提交哈希 / 日期 / 日志链接⟩
```

## 通用排查顺序

1. **确认版本** —— 跑的是不是我以为的那份代码
2. **确认配置** —— 生效值是不是我以为的那个值（外置配置需走缝补通道查询）
3. **确认数据源** —— 查的是不是我以为的那个库
4. **确认灰度** —— 当前用户/流量是否命中新逻辑
5. **确认环境差异** —— 见 [environments.md](environments.md)
6. 以上都确认无误，**才开始怀疑代码逻辑**
